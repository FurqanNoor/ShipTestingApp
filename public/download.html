Start the local app

Install Node.js 22+ and Docker Desktop with Linux containers, or Docker Engine on Linux. Start Docker, extract the ZIP, and run these commands in its hull-test-bench-openfoam folder:

npm ci
npm run cfd:pull
npm run cfd

Open http://127.0.0.1:5173, upload your STL, check units/axes, then select OpenFOAM → Run automatic tests. No numerical values are required. Advanced settings remain available for measured loading and individual tests.

The same programme for every design

150 g, 250 g and 350 g total loads, each in calm water and three regular beam-wave intensities: 12 conditions. Calm towing uses 0.30 m/s in fresh water; waves scale with hull length and run at zero forward speed.

The app detects supported hull geometry, samples a wall-resolution length, estimates CG and inertia from the actual CAD, and solves a stable dry initial roll/trim pose within a default ±20° search. It then schedules coarse/medium/fine meshes, a smaller time-step cap and a 50% larger domain—up to 60 serial solves. Failed or unsuitable conditions stay in the results; no fake readings replace them.

Automatic settings still have assumptions.

The total test loads follow a uniform CAD mass distribution; they are not measured weights inferred from the file. STL files cannot reveal infill, equipment or real cargo positions. CG and inertia remain labelled estimates. Wave motion is constrained to heave and roll about the posed hull’s longitudinal axis, not fully free ship motion.

Download completed or partial Excel/JSON results with assumptions, comparisons and individual solver cases. Tests can be stopped, and recent local records reopened.

Resources and result quality

Pick which tests to run and choose Quick (one fast, rough solve per test) or Full (five solves per test with sensitivity checks; hours to days for all twelve). Solves use several CPU cores and show a live log with time left. Automatic cases are capped at 5 million cells; larger meshes may need more assigned Docker resources. Unsafe, overloaded, unresolved or resource-limited conditions fail or are blocked explicitly. See OPENFOAM.md for setup and limits.

A numerical sensitivity pass checks agreement between these runs. It does not certify physical accuracy. Tow/wave-tank measurements and verified loading are still needed before final competition placements.

Included workflows

  • Calm-water towing resistance from pressure and viscous forces.
  • Zero-speed regular beam waves with free heave and roll.
  • Zero-speed fixed-hull regular head-wave loading.
  • Actual printed-wall geometry, dry-cavity initialization and exact initial hydrostatics.
  • Separate CFD Excel/JSON/case downloads and matching-protocol refinement comparisons.

Advancing waves plus towing current are deliberately unsupported. Native wave boundaries do not automatically supply that physics. Regular waves here are not equivalent to the preview’s irregular sea presets.

What was verified

The current v1.3 version adds automated programme, equilibrium, constrained-inertia, study scheduling and export checks; 209 automated checks and 19 Node server checks passed. Historical v1.2 passed 152 automated checks plus four server-result tests, and v1.1 passed 112 automated checks plus four server-result tests. A real OpenCFD v2312 calm-water smoke completed on 131,396 cells and wrote force data. A native wave/six-DoF startup smoke wrote actual motion data.

These are functional checks, not a physical accuracy certificate. The calm smoke was short and not settled, with additional mesh diagnostics still requiring review. The wave smoke ended before wave travel/startup and did not run a converged propagation mesh. Mesh, time-step and domain convergence, verified mass distribution and physical calibration remain necessary before placements.
